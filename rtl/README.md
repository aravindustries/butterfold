# rtl/ — verified RTL snapshot (for reproducibility)

The exact Verilog that was functionally verified against the golden model. Kept
under version control because part of it is **LLM-authored and therefore not
bit-reproducible** by re-running the generators.

| file | provenance | reproducible? |
|---|---|---|
| `butterfold_top.v` | generated by `gen_top.py` (integrated transceiver) | **yes** — deterministic; `python gen_top.py` reproduces it |
| `twiddle_source.v` | LLM code-agent (functional gate: `tests/modules/tb_twiddle_source.v`) | no — non-deterministic authoring; this is the verified copy |
| `complex_mul.v` | LLM code-agent | no |
| `butterfly.v` | LLM code-agent | no |
| `fdiq_io_adapter.v` | LLM code-agent | no |
| `tdiq_io_adapter_cp.v` | LLM code-agent | no |

| `unified_mixed_radix_core.v` | LLM code-agent | no |
| `scheduler_addr_control.v` | LLM code-agent | no |

## What is what
- **`butterfold_top.v`** is the *working chip*: a self-contained integrated
  Q9.15 datapath that computes the full DFT-s-OFDM TX and RX (EVM 0.0% vs golden).
  It does not instantiate the modules below — it is the numerically-precise
  integration (the int8 modular interfaces cannot reach EVM ≤ 2%; see REPORT.md).
- **The 8 modules** are the agent-authored, functionally-verified decomposition of
  the datapath (each bit-exact to its golden in `tests/modules/tb_*.v`). They
  document the agentic-flow result and the module-level methodology.

## Verify
```bash
python golden/vectors.py
iverilog -g2012 -o /tmp/t.vvp tests/tb_top_golden.v rtl/butterfold_top.v && vvp /tmp/t.vvp
python golden/evm_check.py generated/rtl/top_out.hex tests/vectors/top_gold.hex   # TX  -> EVM 0.0%
iverilog -g2012 -o /tmp/r.vvp tests/tb_top_rx.v rtl/butterfold_top.v && vvp /tmp/r.vvp
python golden/evm_check.py generated/rtl/rx_out.hex tests/vectors/rx_gold.hex     # RX  -> EVM 0.0%
```
