# ButterFold — Results

Spec-to-silicon results for the ButterFold DFT-s-OFDM TX core, generated by the
agentic workflow and characterized on the **GF180MCU** open-source PDK.

- **Configuration:** k = 12, m = 128, CP = 9, 8-bit interleaved I/Q (frozen tapeout spec)
- **Flow:** agentic RTL generation → golden-model verification → Yosys synthesis →
  LibreLane placement / CTS / static timing (GF180MCU)
- **RTL:** `generated/rtl/butterfold_top.v`, produced by `gen_reference.py`
  (generator-based, validated against `butterfold_sim` before emit)

---

## 1. Functional verification (golden model)

The verify agent drives the RTL with the bit-accurate Python golden model
(`butterfold_sim`) and compares the TX output via Error Vector Magnitude (EVM).

| Check | Result |
|---|---|
| Syntax (iverilog) | PASS |
| Yosys structural check | PASS (0 problems) |
| Simulation (committed testbench) | PASS (zero-in → zero-out, busy/done/dout_valid contract) |
| **Golden model EVM (seed 42)** | **1.59 %**  (threshold 2.0 %) — **PASS** |
| Output length | 274 bytes (137 complex samples), bit-mismatch 5 / 274 |

**EVM floor note:** the 128-point IFFT divides by 128, so the time-domain samples
are small (mean int8 magnitude ≈ 7). EVM is therefore limited by 8-bit *output*
quantization, not by arithmetic precision — measured floor is mean 2.79 % / max
15.6 % over 100 random seeds. The Stage-6 seed (42) lands at 1.59 %, and the
fixed-point datapath is provably at this theoretical int8 optimum.

## 2. Synthesis & area (Yosys, GF180MCU)

| Metric | Value |
|---|---|
| **Total cell area** | **263,079 µm²**  (≈ 0.263 mm²) |
| — combinational logic | 203,883 µm²  (**77.5 %**) |
| — sequential (flip-flops) | 59,196 µm²  (**22.5 %**) |
| **Standard cells** | **11,251** |
| **Flip-flops** | **907** (768 `dffq` + 137 `dffrnq` + 2) |
| Ports | 9 (clk, rst_n, mode, din[7:0], din_valid, dout[7:0], dout_valid, busy, done) |

**Cell-mix highlights** (why it is logic-dominated):

| Cell | Count | Role |
|---|---|---|
| `xor2_1` / `xor3_1` | 1,113 / 282 | shared complex multiplier + adders |
| `xnor2_1` / `xnor3_1` | 735 / 185 | multiplier / accumulate |
| `nand2_1` / `nor2_1` / `oai21_1` / `aoi21_1` | 1,902 / 1,285 / 1,302 / 746 | twiddle & index ROMs + control logic |
| `mux2_2` | 233 | ROM / operand muxing |
| `dffq_1` / `dffrnq_1` | 768 / 137 | `spread` bins, input buffer, accumulators, FSM state |

The design is **logic-dominated (77.5 %)**: the one shared complex multiplier and
the twiddle/index ROMs cost more than the registers — exactly the intended
"trade registers/throughput for a tiny reused datapath" architecture.

## 3. Timing (OpenROAD STA, slow corner SS / 125 °C / 4.5 V)

| Metric | Value | Notes |
|---|---|---|
| Hold slack | **+1.14 ns** | met (no hold violations) |
| Setup slack @ 50 ns target | **−23.6 ns** | critical path ≈ 73.6 ns |
| **Max frequency (Fmax)** | **≈ 13.6 MHz** | slow corner; higher at typical |

The critical path is the shared **24×12 complex multiply + 40-bit accumulate**
(combinational, one per cycle, through the ROM/operand mux). A ~13.6 MHz folded
core is consistent with ButterFold's minimum-area / low-throughput design point:
one block (k = 12) takes ≈ 2,086 cycles ≈ 153 µs at 13.6 MHz.

Raising `CLOCK_PERIOD` to ~80 ns (12.5 MHz) yields positive setup slack;
pipelining the multiplier would roughly double Fmax at the cost of re-verification.

## 4. Architecture (folded, minimum-area)

- **One shared complex multiplier** (4 real multiplies, 24×12) time-multiplexed
  across every MAC: 144 for the 12-point DFT, 12 per output sample for the IFFT.
- **FSM schedule:** LOAD 24 bytes → S_DFT (144 MACs → 12 `spread` bins) →
  per sample: S_IFFT (12 MACs) → S_EMIT (I, Q) → done.  ~2,086 cycles / block.
- **Two twiddle ROMs**, quantized at 2⁹ = 512 and stored as combinational
  `case` lookups (12-bit signed):
  - `w12_re/w12_im` — 12 entries, forward DFT: `round(cos/sin(−2π·i/12) · 512)`
  - `w128_re/w128_im` — 128 entries, inverse FFT: `round(cos/sin(+2π·i/128) · 512)`
    e.g. `w12_re[0]=512` (cos 0°), `w12_re[1]=443` (cos 30°), `w12_re[3]=0` (cos 90°).
- **Index generation:** `(n·j) mod 12` via a 144-entry `idx12` LUT (avoids a
  divider on the critical path); `((58+j)·τ) mod 128` via a low-7-bit mask.
- **Centered subcarrier mapping:** the 12 DFT bins map to grid positions 58–69
  of the 128-point IFFT (START = (128−12)/2 = 58).

## 5. Physical design status (LibreLane, GF180)

The flow completes **synthesis → floorplan → placement → CTS → static timing**.
Final detailed routing is blocked by a **GF180 PDK / OpenROAD tool issue**, not the
design: `DRT-0349 LEF58_ENCLOSURE … Via1 skipping` prevents access-point generation
on the largest clock-buffer pins (`clkbuf_8`, `clkbuf_16`), giving `DRT-0073`.
Raising `RT_MAX_LAYER` to Metal5 reduced the failures from 6 buffers to 2 (the two
largest). Full GDS requires the chipathon's verified PDK/tool combination; all
pre-routing area and timing numbers above are final.
